# Маршрут изучения с проверяемыми результатами

Маршрут учитывает большой практический опыт и потребность в фундаментальном языке. Не нужно сначала прочитать всю библиотеку. Лучше вести один собственный кейс через последовательные блоки и после каждого блока уточнять карту.

Источники обозначены номерами из [библиографии](02-literature.md). Большинство пока не проверены в этой сессии. Последовательность — рекомендация для обучения, не доказанный оптимальный курс.

| Блок | Что изучить | Что сделать на своём кейсе | Условие перехода |
| --- | --- | --- | --- |
| 1. Цели и качество | L08: сценарии атрибутов качества; L05/L07 для различения описания и качества. Параллельно начать L24 по [карте чтения](07-righting-software.md) | Записать 5–8 сценариев, ограничения и заинтересованных участников; выписать обещания метода Löwy с точными ссылками | «Хорошо» выражено через конкретное поведение и условия; обещания не смешаны с собственными интерпретациями |
| 2. Основания декомпозиции | L03, затем соответствующие части L24; L04 по концептуальным основам | Сравнить две декомпозиции на одних сценариях изменения, выявить скрываемые решения и неизвестности | Можно объяснить критерий границ и назвать изменение, при котором он перестанет помогать |
| 3. Системный процесс | L12 и L25; L10 по ATAM | Построить 2–3 альтернативы, провести небольшую оценку рисков и компромиссов | Выбор имеет trace от цели к свидетельству; обязательные ограничения отделены от предпочтений |
| 4. Решения и неопределённость | L11/L19; L09 и выбранные части L17 | Записать rationale, диапазоны оценок и условия пересмотра; проверить чувствительность выбора | Видно, какие предпосылки меняют решение и какие данные стоит получить следующими |
| 5. Границы строгой проверки | L14/L15; документация L16 для практики | Выбрать одно взаимодействие, сформулировать safety и предпосылки liveness; сначала разобрать состояния на бумаге, затем при необходимости построить модель | Можно объяснить, что модель подтверждает и как проверить её соответствие реализации |
| 6. Оценка знания | L01/L02 для общей рамки; L22/L23 и свежие обзоры по протоколу | Составить таблицу утверждений и свидетельств; провести ограниченный поиск по одному оставшемуся вопросу | Личный пробел отличён от подтверждённого пробела литературы; следующий вопрос достаточно узок |

Чтение стандартов не должно превращаться в переписывание всего стандарта. На этом этапе нужны определения, ограничения и точные ссылки на релевантные разделы. Работа с платными текстами выполняется через легальный доступ; недоступность полного текста отмечается в журнале.

## Первый небольшой цикл

1. Начать с [вопроса о стоимости реализации 1000 функций](08-modularity-and-cost.md): какой вид затрат должна уменьшать граница? Затем выбрать одно спорное решение из своего опыта и записать контекст без знания результата.
2. Прочитать раздел о сценариях качества в L08 и соответствующий фрагмент L24.
3. Написать заметку: «что утверждается → почему должно работать → что нужно проверить».
4. Сравнить своё решение с одной реальной альтернативой по 3–5 сценариям.
5. Зафиксировать один вывод, одну неопределённость и следующий источник, который может её уменьшить.

Этот цикл даёт материал для размышления быстрее, чем последовательное чтение всех книг. Он не заменяет последующий обзор литературы и не доказывает эффективность метода на одном кейсе.

## Как выбрать дальнейшую ветку

| Что обнаружено | Следующая работа |
| --- | --- |
| Для проблемы уже есть понятный метод и убедительные свидетельства в близком контексте | Освоить и адаптировать метод; проверить выполнение его предпосылок |
| Метод известен, но свидетельства об эффекте неоднозначны | Пилот с явными исходами и затратами; поиск сравнения и отрицательных результатов |
| Критерии ясны, но предсказания ненадёжны | Калибровать модель на данных, делать прототипы, анализировать чувствительность |
| Участники расходятся в целях | Уточнять продуктовый контекст и процесс согласования, а не искать ещё одну структурную метрику |
| Пробел подтверждён актуальным обзором | Сформулировать узкий вопрос, дизайн исследования, альтернативные объяснения и критерий результата |

Возможный исследовательский вопрос: «Повышает ли введение сценариев с порогами согласие независимых оценщиков при одинаковом бюджете анализа для решений об интеграции?» Его новизна пока не проверена. Он существенно точнее вопроса «можно ли сделать архитектуру объективной».

## Итоговый артефакт обучения

По окончании первого маршрута подготовить собственный документ из четырёх частей: модель процесса; разобранный кейс; таблица утверждений и свидетельств; вопросы, которые ещё требуют исследования. Критерий понимания — способность объяснить, где заканчивается доказательство, где начинается прогноз и где необходимо согласование предпочтений.
