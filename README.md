# Исследование архитектурного процесса

Как сделать принятие архитектурных решений воспроизводимым, обоснованным и проверяемым? Какие части этого процесса уже формализованы, а какие требуют суждений о целях, рисках и будущем?

Этот репозиторий — рабочая база исследования архитектуры программных систем. Отправная точка: большой опыт разработки и принятия решений при потребности разобраться в научных основаниях процесса.

**Статус:** начальная карта области и программа исследования, 11 октября 2026 года. Это не завершённый систематический обзор. Большинство первоисточников ещё предстоит прочитать; результаты поиска современной литературы пока отсутствуют. Границы проверки указаны в [журнале источников](research/architecture-process/02-literature.md).

Конкретная отправная точка пользователя — [сомнение о модульности и стоимости реализации 1000 функций](research/architecture-process/08-modularity-and-cost.md). Затем можно перейти к [обзору вопроса](research/architecture-process/01-landscape.md) и [маршруту изучения](research/architecture-process/05-learning-path.md). Для практического входа есть [разобранный пример](research/architecture-process/04-worked-example.md).

## Рабочее правило

Разделять утверждение источника, интерпретацию автора исследования и собственную гипотезу. Для важного вывода записывать область применимости, свидетельства и условия пересмотра. Наличие стандарта, метода или инструмента само по себе не доказывает улучшения результатов его применения.

Для работы достаточно редактора Markdown и Git; установка зависимостей и запуск сервисов не нужны. Материалы можно читать по ссылкам из этого файла.
