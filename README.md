# Обоснованный выбор архитектурных решений

**Насколько существующие методы дают проверяемое основание предпочесть одно архитектурное решение другому и ограничивают возможность оправдать личное предпочтение?**

Отправное наблюдение пользователя: архитекторы могут предложить разные решения одной задачи, обосновать каждое и спорить о превосходстве. Наличие убедительных объяснений ещё не даёт основания для сравнительного выбора. Исследуем правила сравнения альтернатив, независимую проверку оснований, остающееся профессиональное суждение и свидетельства результативности методов. Несколько допустимых решений возможны; распространённость проблемы во всей индустрии заранее не предполагается.

**Статус на 11 октября 2026:** проведено ревью фокуса и ограниченный целевой поиск; после обсуждения уточнён вопрос о сравнительном выборе. Обязательный маршрут содержит три источника. Проверены оглавление учебника, выбранные разделы ATAM и методика, результаты и ограничения эксперимента 2025 года. Систематический обзор и собственный эксперимент не проводились.

Начать с [постановки проблемы](research/architecture-process/00-research-brief.md) и [минимального плана чтения](research/architecture-process/05-learning-path.md). [Результаты ревью](research/architecture-process/09-review.md) объясняют, почему прежний маршрут изменён. Пример с 1000 функций сохранён как один кейс проверки аргумента.

## Рабочее правило

Разделять утверждение источника, интерпретацию автора исследования и собственную гипотезу. Для важного вывода записывать область применимости, свидетельства и условия пересмотра. Наличие стандарта, метода или инструмента само по себе не доказывает улучшения результатов его применения.

Для работы достаточно редактора Markdown и Git; установка зависимостей и запуск сервисов не нужны. Материалы можно читать по ссылкам из этого файла.
